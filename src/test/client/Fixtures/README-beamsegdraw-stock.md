# `beamsegdraw-stock.tsv`: where it came from

tier2's `CBeamSegDraw` (`Start`, `NextSeg`, `End`), from tier2.a's own
`beamsegdraw.o` at `valve-sdk.lock` (the SDK ships no source for it), run
offline by `src/test/oracle/native/beamsegdraw_oracle_test.cpp` before lane
input moved its maths to C# (`src/client/managed/Ropes/BeamSegDraw.cs`,
plan_client_novalve.md §6 C9). `BeamSegDrawOracleTests` replays it.

The scenario is seeded (xorshift32, seed 0x2545F491): 60 random strips of 2 to
16 segments, alternately on the object's own dynamic mesh (the beam executor's
use) and sharing a caller's triangle-list builder from a base vertex, one to
three strips at once (the rope executor's use); a smooth rope-like curve; and
the degenerate shapes (two segments at one point, the camera on the beam's
line, a zero and a negative width). Colours and alphas are k/255, so the byte
CMeshBuilder makes of each names its value.

To regenerate (only when the scenario changes, and say why in the commit):
touch `src/test/oracle/native/beamsegdraw_golden.regen`, run the oracle test,
delete the marker.

## The rows

Floats are their IEEE bits in hex (`%08x`), so a row is the value exactly.

| tag | what |
|---|---|
| `C i mode base cx cy cz` | case `i`: `m` its own mesh, `b` a shared builder whose first `base` vertices earlier strips wrote; the camera `GetWorldSpaceCameraPosition` answers |
| `S n` | a strip of `n` segments follows |
| `G x y z r g b tex width alpha` | one `BeamSeg_t`, field for field |
| `P prim locks unlockVerts unlockIndices draws` | the mesh double's record: the primitive set, `LockMesh` and `UnlockMesh` counts, `Draw` calls |
| `V i x y z bgra u0 v0 u1 v1 sx sy sz tx ty tz` | vertex `i` as stock wrote it: position, the colour's four bytes in buffer order (b g r a), the two texture coordinates, tangent S, tangent T |
| `I ...` | the index buffer: the strip's (`m`, generated by `End`) or every strip's six a quad (`b`) |
