# Where a templated entity ends up — the golden table, and the ONE record of it.
#
# point_template stores each of its sources as a transform in the template's own
# space, and puts a copy back into the world when it is instanced. The whole of
# that is six numbers in and six numbers out:
#
#   capture   matEntityToTemplate = InverseTR( TR(templateOrigin, templateAngles) )
#                                 * TR(entityOrigin, entityAngles)
#   instance  matStoredLocalToWorld = TR(newOrigin, newAngles) * matEntityToTemplate
#             out = ( translation of that, MatrixToAngles of that )
#
# The arithmetic used to be C++ (CPointTemplate::AddTemplateNamed and
# ::CreateInstance, over mathlib's VMatrix) and is now C#. This file is what
# stops the port from quietly meaning something else. TWO tests read it:
#
#   sourcesharp/test/template_transform_test.cpp   — recomputes every row with
#       the REAL VMatrix and asserts the table still describes it. That is what
#       keeps the table a record of native rather than a record of a guess.
#
#   SourceSharp.Tests/TemplateTransformTests.cs    — recomputes every row with
#       the managed Transform and asserts it agrees. That is the one that can
#       actually go red, and it is the point of the file.
#
# A fixture standing in for native drifts silently unless something asserts the
# agreement (docs/writing-tests.md). This is that assertion, in both directions.
