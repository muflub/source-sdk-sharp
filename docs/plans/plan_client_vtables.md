## 1. Design

Everything the server has, the client gets the same way:

- **Engine → managed (C).** Each client EngineApi slot becomes a method of an
  `IShim<Area>` interface on the client's shim root, generated by
  `tools/shim-areas` from `docs/engineapi-areas.tsv` rows with `side` `client`
  (new) or `both` (the 53 that exist). `EngineSide`'s routing then reaches them
  through the vtable exactly as the server's do.
- **Managed → native (E).** Each `ManagedApi` slot becomes a method of a
  managed-built `IManaged<Area>Client` interface, generated by
  `tools/managed-areas` from `docs/managed-interfaces.tsv` client rows, with
  Release at 0 and Validate at 1 (L1), deriving from `IManagedObject` (L1b),
  owned by the client's game DLL object (L2's pattern on `CShellClientDLL`, shell_clientdll.cpp),
  in the client registry (L3), patched in place on reload (L4), checked
  before a reload (L5), counted (L6).
- **Bootstrap.** The client moves to `LoadSideV2` first (CA), which needs the
  struct out-parameter back for the length of the wave: `LoadSideV2` gains a
  trailing `SourceSharpManagedApi *pLegacyManagedOut`, NULL from the server.
  That is the only transitional ABI change; CE-last removes it again, with V1.
  One signature both sides use is simpler than a third load export.

## 2. Steps

Each step is one commit with `make check`; **(live)** steps also pass the live
gate (two passes, with the reload steps).

- **CA. The client loads through `LoadSideV2`.** Shim root (client arms of the
  shared areas only), legacy struct, `pLegacyManagedOut`. `LoadSide` V1 and its
  `Entry` thunk are deleted. ABI bump. **(live)**
- **CB. Shared areas on the client.** The 53 `both` rows get their client arms
  wired, so the client's `EngineSide` routes them through its shim root. Facts:
  `SideAuditTests` waivers shrink; each switched slot reads a real value on the
  client (the "plausible zeros" rule). **(live)**
- **CC1…CCn. Client-only areas**, one `IShim<Area>Client` per commit (grouped
  by the native `.cpp` that owns the bodies: HUD/render, prediction, temp
  entities, input, sound, view, the rest). Each commit adds the TSV rows, the
  generated area, and moves the fill lines out of `sourcesharp_gamesystem.cpp`.
- **CC-last.** The client passes no struct: the fill is deleted, the
  `EngineApi` struct and `LegacyStructs.cs`'s mirror shrink to nothing used,
  `EngineSide`'s struct branch goes. **(live)**
- **CD. The client's managed root.** `ClientModule.BuildManagedRoot` returns a
  root built in `s_ClientVtables`; native accepts it (`ManagedRoot_Accept`'s
  client arm) and holds it on `CShellClientDLL`. `IManagedRuntimeClient` (the
  client's lifetime and frame calls) is the first area. **(live)**
- **CE1…CEn. ManagedApi slots move**, one `IManaged<Area>Client` per commit, in
  the order of their native callers' files (above). Every caller of a slot
  moves in the same commit and the `Entry.cs` thunk goes with it.
- **CE-last.** No `ManagedApi` slot remains: the struct, `pLegacyManagedOut` and
  the client's `Entry.cs` thunks are deleted. ABI bump. **(live)**, with
  `cs_cl_reload` (the client's reload command) as well as `cs_sv_reload`.

### Interop assemblies (the user, 2026-10-01)

Game code stays safe: SourceSharp.Client is compiled without /unsafe ("function-
pointer interop lives in the ABI assembly and game code stays safe"), so the
client's managed-built contracts, generated areas and bindings live in a NEW
assembly, **SourceSharp.Client.Interop** (unsafe), referenced by SourceSharp.Client.
Its bindings call a SAFE host interface (e.g. `IClientRuntimeHost`) that the
client's own types implement. The user's ruling: **do the same for the server.**

- **CI (inside CD).** SourceSharp.Client.Interop: `IClientRuntime`, the generated
  client `ManagedAreas.g.cs`, `ClientRuntimeBinding` over `IClientRuntimeHost`.
- **SI1…SIn. SourceSharp.Server.Interop.** The server's 16 bindings, `IServerRuntime`
  and the generated `ManagedAreas.g.cs` move there, each binding over a safe host
  interface the server's types implement. Measured at 90bd392: 19 Server files use
  `unsafe` -- the 16 bindings, `ManagedAreas.g.cs`, `ServerModule.cs`
  (`BuildManagedRoot`) and `Commands.cs`.
- **SI-last.** SourceSharp.Server is compiled without /unsafe, like the client; a
  fact holds both game assemblies to AllowUnsafeBlocks off.

SI runs after CD and before CE, so CE's 38 areas land in the settled shape.

## 3. Gates

- The live gate must keep a **client** reading in every phase: the HUD's first
  paint and a client-side value written by the server (CLAUDE.md: a datatable
  change is verified only by a full join).
- After CC-last, `EngineApi` is named by nothing but the oracle tests; after
  CE-last, `ManagedApi` likewise. Each is a fact that fails if a name returns.
- Every switched slot needs a fact that its client path is reached (non-zero in
  the positive arm), not just that the build compiles.
