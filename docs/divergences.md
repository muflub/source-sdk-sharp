# Divergences

Where a managed port deliberately does not do what the stock C++ does, and
why. This file is the index: the code owns the detailed note, each row here
names the stock source (file:line at the pristine upstream clone the oracle
reads) and points at the port's own comment. A row with no pointer is a
divergence nobody explained.

| Port | Divergence | Stock | Note |
|---|---|---|---|
| `ss_rocket` (`Rocket.cs`) | The RPG is unguided: no laser-dot steering. | `game/server/hl2/weapon_rpg.cpp` — the laser the shooter paints (`CLaserDot`, :52; `CWeaponRPG::UpdateLaserEffects`, :2200) and, in the single-player SDK's `rpg.cpp`, the missile that turns to it | `Rocket.cs`'s class comment carries the note; the laser designator channel has no managed surface yet. |
| `ss_bolt` world hit | The reflect arm is omitted: a fast bolt meeting a shallow face sticks instead of glancing off at `reflection * speed * 0.75` with `SetGravity(1.0)`. | `game/server/hl2/crossbow.cpp:319-334` (the `hitDot < 0.5f && speed > 100` branch) | Stock's own `Bounces == 0` means the base mover (`FlyingProjectile`) never keeps a bolt flying after `Impact` — it removes on the touch's stop — so there is no host for "keep flying, slower and turned" without a mover hook; the bounce plumbing that would host it is Rocket's `Bounces` path, which the bolt by design does not take. |
| `ss_bolt` world hit | No two-second linger: stock hides the bolt (`EF_NODRAW`) and removes it with `SUB_Remove` at `curtime + 2.0`; ours is removed by the base mover the moment `Impact` returns. | `crossbow.cpp:339-364` | The visible stuck bolt is the `"BoltImpact"` tempent the client's `CrossbowBoltEffect` draws — the entity itself was already invisible (stock's `AddEffects(EF_NODRAW)`) the moment it stuck, so the only observer-visible loss is the glow-sprite fade (`m_pGlowSprite->FadeAndDie`, `crossbow.cpp:366-370`), which has no managed surface. |
| `ss_bolt` world hit | No `g_pEffects->Sparks(GetAbsOrigin())` outside water. | `crossbow.cpp:373-376` | The ported impact chain is `UTIL_ImpactTrace`'s terminal dispatch (`IEngineEffects.ImpactEffect`, the Arsenal port), which carries the surface-property effect; the separate generic-spark call sits on `CEffects`, whose managed surface has no `Sparks` member yet (`ITempEnts.Sparks` is the tempent, a different thing, and stock does not send it here). |
| `ss_bolt` touch guards | Stock picks its branches from `m_takedamage` (`DAMAGE_NO`/`DAMAGE_EVENTS_ONLY` on triggers, `!= DAMAGE_NO` for the body arm) and the early returns for `!IsAlive()` and breakable glass skip the touch entirely; ours takes the body arm for any named entity and the world arm for the invalid handle the mover reports for brushwork, and has no glass or corpse pass-through. | `crossbow.cpp:201-211` (trigger guard), `:208` (the `m_takedamage != DAMAGE_NO` branch test) | The managed mover hands `Impact` only an `EntityHandle` (`FlyingProjectile.TouchedByAnything`), with the world as `EntityHandle.None`; the flags that decide stock's branch (takedamage, liveness, glass) have no managed entity reads wired server-side, and the entity-arm re-trace's own MOVETYPE_NONE guard (via `IEngineNetworking.EntityGetState`) keeps the bolt out of living things regardless. |
| Player shadow stress, friendly slot (`PlayerShadowStress.Measure`, `src/server/managed/PlayerShadowStress.cs`) | Of stock's three tests that sort a contact into the friendly slot (stress zeroed), only the player-held one is ported. A pusher whose owner the player likes (`IRelationType == D_LI`) or a nav-ignored pusher (`IsNavIgnored()`) loads slot 2+ here, where stock zeroes it, so `PhysicsDamageQueue`'s stress crush can fire against a friendly. | `game/server/physics_impact_damage.cpp:543-555` (`CalculateObjectStress`'s `outIndex = 1` arms) | Unreachable today, which is why the arms are absent and not wrong: HL2MP's rules never fill the relationship table (nothing is `D_LI`), and only `logic_navigation` and HL2's NPCs set nav-ignore. Re-add both when an NPC or a nav-ignoring pusher exists. Each needs a per-contact fact the fill cannot read: D_LI a managed-built relationship query (a `docs/managed-interfaces.tsv` row, the player against the contact's owner handle); nav-ignore an entity fact this hierarchy does not store (stock's `m_flNavIgnoreUntilTime`), so a per-handle read on the shim. `PhysicsObjectStress`'s friendly slot already takes the result (`StressContact.Friendly`); `PlayerShadowStress`'s summary carries the note. |
| `ITeams.Join` (`Teams.cs`) | A join is the store plus the announcement only: no model switch, and no suicide for a player who changes sides mid-round or for a living teamed player who joins the spectators; the observer half (including the spectator's strip-of-items) is the Observers'. | `src/game/server/hl2mp/hl2mp_player.cpp:958-1006` (`CHL2MP_Player::ChangeTeam`: `SetPlayerTeamModel`/`SetPlayerModel` :990-996, spectator `RemoveAllItems` :998-1002, mid-round team switch `CommitSuicide` :1004-1007 — all hanging off a `CBasePlayer`), `:1027-1036` (`CHL2MP_Player::HandleCommand_JoinTeam`'s spectator arm: `CommitSuicide` and the frag refund before `ChangeTeam( TEAM_SPECTATOR )`) and `src/game/server/baseentity.cpp:4947` (`CBaseEntity::ChangeTeam`, the assignment alone) | The stock behaviours hang off a `CBasePlayer` this build has no equivalent of; the standalone player is not a `CBasePlayer`. The store and the `player_team` event are the parts that exist here; `Teams.cs`' class comment names the absence. |
| `ITeams.Join` with no `IJoinTeamPolicy` (`Teams.cs`) | With no mod policy, `jointeam 2`/`3` puts the player on that team. Stock HL2DM with teamplay off (the deathmatch this build runs) forces every non-spectator join to `TEAM_UNASSIGNED` (0): `jointeam 2` leaves a deathmatch player unassigned. | `src/game/server/hl2mp/hl2mp_player.cpp:971-975` (`CHL2MP_Player::ChangeTeam`: `if ( HL2MPRules()->IsTeamplay() != true && iTeam != TEAM_SPECTATOR ) iTeam = TEAM_UNASSIGNED;`) | The team is the seam stage 0.5 exists to open for a mod (TF2's `TfTeams` policy, `docs/plans/tf2/stage2_server_core.md`), and its live gate (`tools/laneD-live-probe.py`) proves the store end to end by reading team 2 back. This build has no teamplay rule to key the stock override on; a mod that wants HL2DM's answer registers a policy that refuses 2 and 3. `ITeams.Join`'s comment names the divergence. |
| `IPlayerInfo::ChangeTeam` (`shell_playerinfo.cpp`) | Still a refusal (`SS_PLAYERINFO_REFUSAL_CHANGE_TEAM`), even though the team became real storage and the managed route is the `PlayerSetTeam` slot: a plugin's mutator that silently did nothing is the §7 silent no-op, so it says so instead. `GetTeamIndex` by contrast reads `m_iTeamNum`. | `src/game/server/player.h` (`IPlayerInfo::ChangeTeam`, stock changes the team) | Pinned by `playerinfo_block_test`'s refusal count and its named-refusal list; the caller who wants the change is `ITeams.Join`, not this shim. |
| `GameModes` round reset (`Modes/GameModes.cs`) | A mode switch's round reset (`GameModes.SwitchTo`'s flush; a level change loads fresh entities and walks none) resets the live entities in place — every spawned entity gets `ScriptedEntity.RoundReset`, once, and the count is logged (`round reset: N entities`) — instead of stock's `CleanUpMap`, which removes every entity players do not anchor and reloads the map entities from their entity strings. Players are kept (ruling D6's switch keeps the session), and an entity whose class never overrode `RoundReset` keeps whatever it accumulated. | `src/game/shared/teamplayroundbased_gamerules.cpp:2891-2975` (`CTeamplayRoundBasedRules::CleanUpMap`: the `UTIL_Remove` walk past `RoundCleanupShouldIgnore`, then the `CTeamplayMapEntityFilter` reload from `g_MapEntityRefs`) | The managed entities are live objects whose state a map entity string never held (a logic_case's counters, a mode's own bookkeeping): a rebuild-from-string would keep THAT state by accident instead of clearing it on purpose. The in-place walk makes clearing opt-in per class (`ScriptedEntity.RoundReset`'s comment); an entity with per-round state that forgets to override keeps it, which is the class author's bug to own, and `GameModesTests.ASwitchResetsEveryLiveEntityExactlyOnce` pins the walk. |
| `MultiplayerAnimState` (shared/managed/Anim) | The server's targets answer pose-parameter NAMES with no index (their `LookupPoseParameter` is the shell's client-only arm): a server machine that is asked to pose poses nothing, and the whole pose-parameter half of the class is client-live only. | `game/shared/Multiplayer/multiplayer_animstate.cpp:1566,1689,1702` (the three ComputePoseParam_*) | The shell has no server pose-parameter-by-name binding (`Standalone_LookupPoseParameter` is CLIENT_DLL); the server's animation state exists to answer the chain and hold the facts, not to pose — the pose driver that will one day want it is the row that closes this. |
| `MultiplayerAnimState` (shared/managed/Anim) | The server's gesture pushes stay in the target's own memory: no shell layer arm is written server-side. | `multiplayer_animstate.cpp:1224` (`ResetGestureSlot`/`AddToGestureSlot` through `CBaseAnimatingOverlay`, which replicates the overlay array) | There is no server `SetAnimLayer` binding at this base (the overlay replication channel is the client's); the table the target mirrors is complete, so the day a server pose driver exists it reads the same bookkeeping. |
| `MultiplayerAnimState` (shared/managed/Anim) | `CalcMovementPlaybackRate` ports the LIVE HL2 rule — a zero/unmeasurable ground speed plays at 1 — and not the file's own `flGroundSpeed < 0.001f → 0.01f` arm. | `multiplayer_animstate.cpp:1070-1085`; the live rule is `CBasePlayerAnimState::CalcMovementPlaybackRate`, `game/shared/base_playeranimstate.cpp:504-521` | Nothing in the HL2MP build ever called the file's version (CSDKPlayerAnimState overrides it); this build's client animator had always followed the live rule and the phase's gate is "animate as before". |
| `MultiplayerAnimState` (shared/managed/Anim) | `ComputeMainSequence` measures the rate against the sequence ABOUT TO PLAY, where stock's `CalcMovementPlaybackRate` measured the one currently on the body. | `multiplayer_animstate.cpp:1009,1070` (GetCurrentMaxGroundSpeed reads `GetSequence()`) | In this hierarchy the hand-over is the moment the rate is chosen; measuring the stale sequence would play a new gait at the old gait's feet-per-second for one frame per change — a limp on every start. The hand-over edge itself (restart only on an activity change) is stock's `ResetSequence` (`:1206`). |
| `MultiplayerAnimState` (shared/managed/Anim) | The gesture events do not fire the outgoing gesture's animation-event-to-completion pump when a gesture is replaced (stock's client arm ran its events to cycle 1). | `multiplayer_animstate.cpp:494-510` (`RunGestureSlotAnimEventsToCompletion`) | The pump this build has watches the SHELL's clock, and a replaced slot's tail window is gone before the pump's next frame; the bookkeeping cycle is still walked to 1 so the autokill timing is stock's. |
| `MultiplayerAnimState` (shared/managed/Anim) | `ComputePoseParam_AimYaw` never writes the body's angles: no server `SetAbsAngles`, no client render-angle store, so the model's root is drawn at the body's own facing (`IAnimTarget.BodyYaw`), not at the converged feet yaw. To compensate, a target whose root does not follow the feet (`IAnimTarget.RootFollowsFeet` false: `EngineAnimTarget`, both sides) has the torso dial posed against the drawn root, `body_yaw = −(eye − BodyYaw)`, instead of stock's `−(eye − feet)`; the feet still converge by stock's rule and `RenderYaw` keeps them. A remote player (eyes = body) therefore reads `body_yaw` 0 after a standing turn under 45°, where stock's formula on this root would turn the torso past the eyes. | `multiplayer_animstate.cpp:1760-1762` (the render-angle write), `:1780` (the dial) | The movement code is authoritative for the body's angles in this build; an animation state that wrote them would be the animation making a physics decision (the machine's rule). Posing against the drawn root keeps stock's picture (torso on the eyes) on the root this build has; `AnimStateMachineTests.ARootDrawnAtTheBody*` and `PlayerAnimatorTests.ARemotePlayerStandingAfterASmallTurnHasNoTorsoTwist` pin it, and the stock arm's facts run with the root following the feet. |
| `MultiplayerAnimState` (shared/managed/Anim) | `ShouldUpdateAnimState`'s local-player half is the target's `ShouldDrawLocalPlayer` read; the engine's demo-camera exception is absent. | `multiplayer_animstate.cpp:1340-1351` (`CBasePlayer::ShouldDrawLocalPlayer`) | There is no managed demo-camera surface at this base; the local player's own visibility read is what the targets can answer. |
| `Hl2PostureLayer` (shared/managed/Anim) | The layer decides the gait from the posture table, not from stock's per-weapon `CalcMainActivity` (which picks `ACT_HL2MP_*_PISTOL`/`_GRENADE` by the held weapon). | `game/shared/hl2/csdk_playeranimstate.cpp` (the weapon switch) | This build's animator always resolved by the posture's activity LIST (melee first, pistol as the list's next answer), which gets the same result without a weapon read; the day a weapon-precise layer wants it, it is a chain layer below this one — that is what the seam is for. |
| `MultiplayerAnimState` (shared/managed/Anim) | The TF-only arms are excluded: the `TF_CLIENT_DLL || TF_DLL` blocks (reload attributes that speed up first-person reload, `:207,230,245,268,283`), and `CUSTOM_GESTURE_SEQUENCE`'s body (commented-out in stock) stays out. | `multiplayer_animstate.cpp:25,192,207,230,245,268,283` | The phase's ruling: the TF2 layer adds those in its own chain layer in Stage 1 (`docs/plans/plan_tf2_port.md` §2), which is why the chain, not `#ifdef`s, is the shape here. |
