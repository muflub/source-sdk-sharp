# Divergences

Where a managed port deliberately does not do what the stock C++ does, and
why. This file is the index: the code owns the detailed note, each row here
names the stock source (file:line at the pristine upstream clone the oracle
reads) and points at the port's own comment. A row with no pointer is a
divergence nobody explained.

| Port | Divergence | Stock | Note |

| `GameModes` round reset (`Modes/GameModes.cs`) | A mode switch's round reset (`GameModes.SwitchTo`'s flush; a level change loads fresh entities and walks none) resets the live entities in place — every spawned entity gets `ScriptedEntity.RoundReset`, once, and the count is logged (`round reset: N entities`) — instead of stock's `CleanUpMap`, which removes every entity players do not anchor and reloads the map entities from their entity strings. The in-place walk makes clearing opt-in per class (`ScriptedEntity.RoundReset`'s comment); an entity with per-round state that forgets to override keeps it, which is the class author's bug to own, and `GameModesTests.ASwitchResetsEveryLiveEntityExactlyOnce` pins the walk. |

| `MultiplayerAnimState` (shared/managed/Anim) | `ComputePoseParam_AimYaw` never writes the body's angles: no server `SetAbsAngles`, no client render-angle store, so the model's root is drawn at the body's own facing (`IAnimTarget.BodyYaw`), not at the converged feet yaw.
